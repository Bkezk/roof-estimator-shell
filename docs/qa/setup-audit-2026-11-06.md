## Findings (not fixed)

1. **An unknown `?tab=` value shows a blank page.** `/setup?tab=bogus` (a mistyped or stale link)
   renders the four tabs all inactive and no card below them. The page's `validateSearch` returns
   `{}` for an unknown value, but the value still reaches the page (the router merges the
   validated search over the raw one, so a stripped key survives), and the Tabs component is
   given a value that matches no tab. `?tab=materials` and the others work. Fix: on the page,
   treat a value outside `SETUP_TABS` as the rates (one line).
2. **Two cards word a failed save in raw terms.** A refused rates save or confirm says "Failed
   to fetch" (and the drivers card would say the same), while the checklist and materials cards
   say "No signal. Check your connection and try again." (`plainErrText`). Fix: the same helper
   on the rates and drivers cards.
3. **A materials save re-sends the markup even when it did not change.** The database then writes
   `service_settings.updated_at` (seen: 13:58 today) with the same markup. Harmless, but the
   stamp no longer means a setting changed. Fix: send the markup only when it differs from the
   loaded one.
